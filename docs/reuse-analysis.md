# Reuse Analysis

**Research snapshot:** 2026-10-30. This is a source review, not a dependency approval or vulnerability clearance. No packages were installed, copied, or audited against a project lockfile. Version numbers below are observed release/source snapshots, not pins; re-check stable releases, advisories, compatibility, and the complete dependency tree when Milestone 01 is approved.

## Findings and recommendations

| Area | Candidate and evidence inspected | Recommendation / alternative | Caveat |
|---|---|---|---|
| Authentication | ASP.NET Core Identity .NET 10 documentation and official source reference. It provides user/password, roles, claims, tokens, and account lifecycle; Identity uses framework password hashing. | Use Identity, as required. Use cookie authentication for the same-origin browser app; do not build passwords, sessions, lockout, or reset tokens from scratch. | Identity is not a tenant authorization system. School membership, student mapping, CSRF, secure cookies, account provisioning, and API authorization remain application responsibilities. |
| Persistence | EF Core indexes, composite relational model support, global filters, and Npgsql EF Core provider docs/release notes. Npgsql provider 10.0.x supports EF Core 10; v10.0.3 was listed in releases. Its source license is the permissive PostgreSQL License. | EF Core + Npgsql provider for PostgreSQL, as specified. Keep PostgreSQL in local/test/production to avoid provider differences. | Validate migrations/constraints on PostgreSQL itself; SQLite/in-memory substitutes do not prove PostgreSQL behavior. Audit actual package transitive dependencies when locked. |
| Tenant isolation | EF Core docs show tenant IDs can be placed on a `DbContext` and applied as global query filters. PostgreSQL RLS is available, but owners and privileged roles can bypass policies. Finbuckle.MultiTenant 10.1.3 advertises .NET 10 support and tenant resolution/data isolation. | Start with explicit server-resolved school context, scoped application queries, authorization, composite school keys/FKs, and isolation tests. Treat EF filters as an extra guard. Avoid a library until it removes a demonstrated need. | Finbuckle's README announces an Open Source Maintenance Fee for revenue-generating use; its displayed effective date is malformed and the linked terms file returned 404 during this review. Do not adopt until terms are obtained and commercially reviewed. RLS is not the sole boundary. |
| Routing/build | Official React, Vite, and React Router docs; React/Vite/Router repository licenses and Router package metadata. Vite requires Node 20.19+ or 22.12+; the installed Node 24.20.0 meets that stated floor. React Router's current release page lists v8.5.1 and v7.18.5; package manifest is MIT. | Use the requested React + TypeScript + Vite + React Router direction. Choose a stable React Router major during scaffold after checking API and ecosystem compatibility. | Node compatibility says nothing about package security or target browser support; check lockfile and deployment browsers. |
| Server/API state | TanStack Query docs describe caching, synchronization, invalidation, mutations, pagination, and background refresh. Repository package metadata: `@tanstack/react-query` 5.105.0, MIT; direct runtime dependency is `@tanstack/query-core`, React is a peer. Recent release activity was visible on 2026-10-26. | Recommended for API/server state, matching the requested stack. Keep small ephemeral UI state in React; no Redux state container is justified by current scope. | Caching student records increases sensitivity: clear/query-scope cache on logout and school switch; do not put secrets or unnecessary private data in persisted caches. No version-specific advisory audit was possible without a selected lockfile. |
| Forms and validation | React Hook Form docs and package source: v7.91.0, MIT, no direct runtime dependencies; stable v7 releases are active and v8.0.0-beta.5 is pre-release. Zod docs and source: v4.6.7, stable v4, MIT, zero external dependencies. | Recommended pair for non-trivial client forms, with server-side validation remaining authoritative. Native browser constraints are enough for trivial fields. | `@hookform/resolvers` is a separate package if `zodResolver` is used; inspect its current source/license/dependencies before adding it. Zod validation is not authorization or backend input validation. Prefer stable RHF v7 over the observed v8 beta for initial work. |
| UI components | Material UI repository README, core package metadata, release page, and MIT license inspected. Stable release v9.5.0 exists; the current main package metadata is v10.0.0-alpha.0. Package manifest shows a meaningful dependency/peer set (`@mui/system`, `@mui/utils`, Popper, Emotion peers, etc.). | MUI core is a reasonable candidate for consistent admin forms/tables/dialogs and accessibility primitives; evaluate a small prototype before adoption. Alternative: native HTML/CSS and a small set of custom components, which minimizes dependencies but costs design/accessibility work. | Do not use the v10 alpha for the initial product. MUI X packages have separate package-level licensing/feature tiers; inspect each package before use. Transitive vulnerabilities and browser/accessibility behavior are not cleared here. |
| Backend tests | ASP.NET Core integration-test guidance supports test-server based API integration and recommends focused infrastructure coverage; current examples support xUnit, NUnit, or MSTest. xUnit project source is Apache-2.0; its release page lists v3 4.0.2 and project documentation says v3 supports .NET 8+. | Use xUnit as specified; combine fast application/unit tests with focused API/PostgreSQL integration tests for constraints, cookies, and tenant denials. | Pick compatible stable xUnit/test SDK versions together at scaffold time. Do not use EF in-memory tests as proof of PostgreSQL constraints. |
| Frontend tests | Vitest is Vite-powered; its guide requires Vite >=6.4 and Node >=22.12. The main package source showed 5.1.0-beta.1, so a stable version must be chosen from releases. React Testing Library docs emphasize user-facing DOM behavior; v16.3.3 release (2026-08-27) and package metadata show MIT, with `@testing-library/dom` as a peer. Playwright docs describe browser E2E; v1.64.1 release and Apache-2.0 source license were inspected. | Recommended: stable Vitest + React Testing Library for unit/component tests; Playwright for a small number of critical sign-in, parent isolation, and teacher workflows. | RTL requires DOM/test dependencies; Playwright downloads browser binaries and adds CI/runtime cost. Install only after choosing versions and auditing transitive dependencies. |
| Logging | Microsoft .NET logging docs describe structured `ILogger` APIs and built-in providers; no external logging package is required initially. | Begin with `ILogger<T>` and approved providers. Consider Serilog or another provider only when a specific sink/retention/structured-query requirement is accepted. | Do not log child/parent data, credentials, or health notes. Provider configuration and log access/retention are security controls. |

## Alternatives considered

- **Custom authentication/password handling:** rejected. It duplicates framework security-sensitive functionality and adds avoidable risk.
- **Global Identity roles as the only school authorization:** rejected. Roles do not establish which school, class, or student a user may access.
- **Per-tenant database or schema, microservices, and message brokers:** deferred. The MVP has one school and the brief prefers shared-schema `SchoolId` isolation; these add operational complexity without a demonstrated need.
- **EF global filters as the only tenant control:** rejected. Filters can be bypassed and do not replace authorization or same-school relational constraints.
- **Finbuckle.MultiTenant:** reviewed as an alternative, not adopted. Reconsider only if explicit context becomes repetitive/fragile and commercial maintenance terms are clear.
- **MUI X advanced components:** not selected. Review each package's license and price/feature tier independently.
- **Unlicensed sample code:** prohibited; no public source was copied.

## Security and licensing status

- Focused implementation entry points were inspected for [ASP.NET Core Identity](https://github.com/dotnet/aspnetcore/tree/main/src/Identity), [Npgsql's EF configuration](https://raw.githubusercontent.com/npgsql/efcore.pg/main/src/EFCore.PG/Extensions/NpgsqlDbContextOptionsBuilderExtensions.cs), [TanStack Query](https://raw.githubusercontent.com/TanStack/query/main/packages/react-query/src/useQuery.ts), [React Hook Form](https://raw.githubusercontent.com/react-hook-form/react-hook-form/master/src/useForm.ts), [Zod parsing](https://raw.githubusercontent.com/colinhacks/zod/main/packages/zod/src/v4/classic/parse.ts), [MUI Button](https://raw.githubusercontent.com/mui/material-ui/master/packages/mui-material/src/Button/Button.js), and [React Testing Library](https://raw.githubusercontent.com/testing-library/react-testing-library/main/src/pure.js). Their public documentation, package metadata, release activity, and license evidence were also checked.
- For xUnit, Vitest, Playwright, and Finbuckle, this milestone checked project documentation/README, release or source-tree metadata, and license evidence; it did not audit their full implementation. Finbuckle was not adopted, and its commercial fee terms could not be retrieved.
- No source was copied.
- This review does **not** establish vulnerability-free status. There is no Preschool Connect lockfile or selected package version set, so there is no meaningful complete transitive audit. At adoption, inspect GitHub/npm/NuGet advisories and run the applicable package-manager/dependency scanner on the locked graph.
- MIT, Apache-2.0, and PostgreSQL License are generally permissive, but retain required copyright/license and notice files for distributed artifacts. Confirm the exact package license and any bundled third-party notices for the chosen version.
- The candidate package versions in this report are not endorsements of every version or transitive dependency.
